# 必要実装の整理

## 1. 確定している業務ルール

- 対象者は同じ家で暮らす2人。
- 2人ともiPhoneを利用する。
- 電気・ガス・水道など、対象となる請求金額の全額を在宅時間比率で分ける。
- 基本料金と従量料金は分離しない。
- 負担割合は `個人の有効な在宅時間 ÷ 2人の有効な在宅時間合計` とする。
- 位置座標や外出先は保存せず、自宅への到着・出発イベントだけを保存する。
- 時刻はすべて `Asia/Tokyo` を基準にする。

## 2. 在宅イベント

### 入力

```json
{
  "token": "ユーザー別トークン",
  "user_id": "user_A",
  "event": "ENTER",
  "timestamp": "2026-11-13T18:00:00+09:00",
  "event_id": "iPhoneで生成したUUID",
  "source": "ios_shortcut"
}
```

- `event` は `ENTER` または `EXIT` のみ。
- `timestamp` はタイムゾーン付きISO 8601形式を必須とする。
- `event_id` は再送時にも同じ値を使う。省略時は主要フィールドから決定的なIDを生成する。
- 受信時刻もサーバー側で別に記録する。

### 異常系

- 同じイベントIDの再送は新しい行を作らず、成功済みの結果を返す。
- 同じユーザーで `ENTER → ENTER` または `EXIT → EXIT` になった場合は、削除せず `NEEDS_REVIEW` として保存する。
- 最新イベントより古いイベントは `OUT_OF_ORDER` として要確認にする。
- 許容範囲を超えて古い日時・未来日時は拒否する。許容範囲は設定シートで変更可能にする。
- 未登録または無効なユーザーは拒否する。
- 認証トークンはユーザーごとに検証する。

## 3. 在宅時間集計（第2段階）

- 対象期間の開始時点より前にある最後の正常イベントから、期間開始時の状態を復元する。
- `ENTER` から次の `EXIT` までを在宅区間とする。
- 月をまたぐ在宅区間は対象期間と重なる部分だけを集計する。
- 連続イベント、欠落、時系列逆転、位置情報無効期間は勝手に推測せず「判定不能時間」とする。
- 元イベントを直接上書きせず、修正テーブルに追記して監査可能にする。
- 2人それぞれについて、有効在宅時間・判定不能時間・対象期間全体を表示する。

## 4. 請求按分（第3段階）

- 請求項目、請求元、表示名、有効/無効、表示順を設定表で管理する。
- 対象期間、請求額、入力者、入力日時、計算状態を請求履歴に保存する。
- 2人の在宅時間合計が0の場合は自動確定せず、均等割りまたは手動入力を求める。
- 片方だけが0で、もう片方に有効在宅時間があれば、原則として 0% / 100% とする。
- 端数は一方を四捨五入し、もう一方を `請求総額 - 一方の負担額` として必ず総額を一致させる。
- 計算に使用した在宅時間、比率、丸め前金額、確定金額を履歴として残す。

## 5. LINE Bot（第4段階）

- LINEユーザーとシステムユーザーを事前に対応付ける。
- 設定表にある有効な請求項目だけを候補として提示する。
- 請求項目、金額、対象開始日、対象終了日を確定してから計算する。
- 入力途中の状態を保持し、キャンセル・訂正を可能にする。
- 結果には2人の在宅時間、割合、負担額、判定不能時間を含める。
- LINE署名を検証し、重複Webhookイベントを排除する。

## 6. 運用上の前提

- iOSのジオフェンスは検知遅延やイベント欠落があり得るため、金額計算前に要確認イベントを確認できるようにする。
- 位置情報の「常に許可」、ショートカットの自動実行、ネットワーク状態を定期的に確認する。
- 自宅付近で実測し、ジオフェンス半径を調整する。
- 友人本人の明示的な同意を得て利用する。
